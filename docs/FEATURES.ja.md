# 機能仕様書

[English version here](FEATURES.md)

バージョン: 1.2.1
対象: Windows向けローカルMarkdownビューアー(ソースからならmacOS/Linuxでも動作)

## 1. 概要

MD Viewer は、ローカルファイルを閲覧するための読み取り専用Markdownビューアーである。単一の `.md` ファイル、またはフォルダ配下の `.md` ファイル群をブラウザ上でHTMLとして表示する。GitHub Flavored Markdown、図表、数式、検索、ライブリロードに対応する。編集機能は持たない。

配布形態は3種類。

| 形態 | 必要環境 | 用途 |
| --- | --- | --- |
| ソース起動 | Node.js 20.6 以上 | 開発、Windows以外のOS、カスタマイズ |
| ポータブル版 `.exe` | 不要(単体で完結) | Windows、インストール不要、USB/D&D向き |
| インストーラー版 `.exe` | 不要(単体で完結) | Windows、スタートメニュー/デスクトップ、PATH登録可 |

## 2. 機能要件

### 2.1 表示モード

- **単一ファイルモード**: `mdv <file>.md` で1ファイルのみ表示。サイドバーのツリーは非表示(「フォルダを開く」ボタンは引き続き使用可能)。相対リンク・相対画像はそのファイルの親フォルダを基準に解決する。
- **フォルダモード**: `mdv <folder>` でフォルダ配下の全 `.md`/`.markdown` をツリー化する(ドットファイル、`node_modules`、Markdownを含まないフォルダは除外)。ツリー項目のクリックでページ全体を再読込せずに表示を切り替える(ハッシュルーティング: `#/相対パス.md#見出しID`)。
- **実行中のフォルダ切替**: サイドバー上部の「フォルダを開く」ボタンで絶対パスを入力すると `POST /api/change-dir`(§3参照)を呼び出し、プロセスを再起動せずにサーバーのルートを切り替える。ファイル監視は新ルート向けに破棄・再作成され、レンダリングキャッシュは全消去され、クライアントはツリーを再構築してURLハッシュを新ルートの初期ドキュメントにリセットする。
- **前回開いたフォルダの記憶**: フォルダ切替が成功するたびに `localStorage` へ保存する。URLにフラグメントがない状態で新規起動すると、何かを表示する前にその記憶したフォルダへ自動的に切り替える。これにより、(常に自身のサンプル/カレントフォルダを指した状態で起動する)アプリをダブルクリックしても、サンプルではなく前回開いていたフォルダがそのまま開く。記憶したフォルダが存在しなくなっていた場合は、アラートを出さず静かに失敗し、古い記録を消去した上でサーバー起動時のフォルダを表示する。

### 2.2 Markdownレンダリングパイプライン

[unified](https://unifiedjs.com/)(remark→rehype)によるサーバーサイドレンダリング。処理順序は固定:

```
remark-parse → remark-frontmatter → フロントマター抽出 → remark-gfm → remark-emoji → remark-math
  → [ユーザー定義remarkプラグイン] → remark-rehype(allowDangerousHtml)
  → rehype-raw → rehype-slug → rehype-katex
  → mermaidブロックの分離 → 未知言語のクラス除去
  → @shikijs/rehype(ライト/ダーク二重テーマ) → 相対リンク・画像の書き換え
  → 見出し収集 → [ユーザー定義rehypeプラグイン] → rehype-stringify
```

- **GFM**: テーブル、タスクリスト(チェックボックス)、打ち消し線、自動リンク、脚注(本文への相互参照付き)。
- **生HTML**: `rehype-raw` によりMarkdown内のインラインHTML(`<details>` など)をそのまま描画する。サニタイズは行わない(§5 セキュリティモデル参照)。
- **シンタックスハイライト**: [Shiki](https://shiki.style/) によるライト/ダーク二重テーマ(既定は `github-light` / `github-dark`)。1回のレンダリングで両テーマ分の色情報をCSSカスタムプロパティとして埋め込むため、UIテーマ切替時にコードブロックはサーバーへ再問い合わせせず即座に切り替わる。未知の言語指定は `language-*` クラスをハイライト処理前に除去するため例外が発生せず、プレーンな `<pre>` にフォールバックする。
- **Mermaid**: ` ```mermaid ` ブロックはサーバー側で `<div class="mermaid-block"><pre class="mermaid-src">…</pre></div>` に変換する(MermaidはDOMを要求するため、実際の描画は同梱の `mermaid.min.js` によりクライアント側で行う)。図の構文エラーはページ全体を壊さず、エラーメッセージと元ソースをインラインで表示する。
- **数式**: `remark-math` + `rehype-katex`(KaTeX)。インライン `$...$` とブロック `$$...$$` に対応。レンダリングエラーは例外を投げず、エラー色でインライン表示する。
- **絵文字**: `remark-emoji` が標準で有効(`{ accessible: true }` により各置換を `<span role="img" aria-label="…">` で囲む)。`:smile:` のようなGitHub形式のショートコードが設定不要でUnicode絵文字として描画される。
- **フロントマター**: YAMLフロントマターは(`yaml` パッケージで)解析されて本文からは除去されるが、解析結果のオブジェクトはクライアントへ `payload.frontmatter` として返され、ドキュメント上部にカードとして表示される(§2.3参照)。
- **大容量ファイル**: 2MBを超えるファイルは全処理をスキップし、通知バナー付きのエスケープ済み `<pre>` として表示する(レンダリング時間の上限を担保するため)。

### 2.3 ナビゲーション

- **サイドバーのファイルツリー**: フォルダは初回展開時に初めて子要素をDOMへ描画する遅延方式。日本語ロケール対応のコレータでソートし、フォルダを先に並べる。ドキュメントを開くと祖先フォルダが自動的に展開・強調表示される。
- **ツリーのキーボード操作**: roving tabindex による `role="tree"` パターンを実装。`↑`/`↓` で表示中の行を移動、`→` は折りたたまれたフォルダを展開(展開済みなら最初の子へ移動)、`←` は展開中のフォルダを折りたたむ(折りたたみ済み・ファイルなら親フォルダへ移動)、`Home`/`End` で最初/最後の行へ、`Enter`/`Space` でフォーカス中の行を活性化(ファイルを開く、またはフォルダの開閉)。フォルダ行は `aria-expanded` を公開する。
- **相対リンク**: 他の `.md`/`.markdown` へのリンクはアプリ内のハッシュルーター(`#/path.md` または `#/path.md#fragment`)に書き換えられ、SPA内遷移を維持する。Markdown以外へのリンクは `/raw/<path>` に書き換えられ新規タブで開く。ページ内アンカー(パスなしの `#fragment`)はクライアント側で捕捉しスクロールする。
- **画像**: 相対パスの画像は `/raw/<解決済みパス>` に書き換えられ、パストラバーサル対策込みでディスクから配信される(§5参照)。
- **アウトライン(目次)**: 現在のドキュメントの見出し(h1〜h6)を階層インデント付きで列挙。クリックでスクロール、スクロール位置に応じて現在の見出しを自動ハイライト(スクロールスパイ)。ビューポート幅が約1100px以上では右側の常設パネル、それ未満では右からスライドインするドロワーになる(ツールバーのボタンで開閉、バックドロップクリック・`Esc`キー・目次項目の選択でも閉じる)。
- **フロントマターカード**: YAMLフロントマターを持つドキュメントでは、本文の直前にカードを挿入する。`title` フィールドは見出しとして、日付系フィールド(`date`/`created(_at)`/`updated(_at)`)は `ja-JP` ロケールで整形して、タグ系フィールド(`tags`/`tag`/`categories`/`category`、文字列でも配列でも可)はピル状バッジとして、それ以外のスカラー・配列値は単純なキー/バリューの表として表示する。フロントマターがない(または該当フィールドがない)ドキュメントではカード自体を表示しない。
- **印刷用スタイルシート**: `@media print` により、ツールバー・サイドバー・アウトラインパネル・コピー ボタンを非表示にし、画面用のスクロールシェルレイアウトを解除して文書全体が複数ページにわたって自然に流れるようにし、現在のテーマに関わらずライトで高コントラストな配色を強制し、コードブロックをスクロールではなく折り返し表示にし、Mermaid のSVGをページ幅に収まるよう縮小し、外部リンクにはリンクテキストの後にURLを併記し、見出し・表・コードブロック・フロントマターカード・図がページ境界で分断されないようブラウザにヒントを与える。

### 2.4 検索

| 種別 | 対象範囲 | 挙動 |
| --- | --- | --- |
| ページ内検索 | 表示中のドキュメント | 大文字小文字を無視した部分一致。レンダリング済みテキストノードを対象(SVG/KaTeX/Mermaid内部は除外)。全一致箇所をハイライトし、`Enter`/`Shift+Enter` で巡回、最大500件でハイライトを打ち切る。ショートカット: `/`。 |
| フォルダ横断検索 | ルート配下の全 `.md` | 大文字小文字を無視した部分一致。索引を持たない逐次ファイルスキャン。1ファイルあたり最大5行、全体で最大200件のマッチを前後スニペット付きで返す。結果クリックで該当ファイルを開き、同じ検索語でページ内検索を再実行する。 |

### 2.5 テーマ

ツールバーのボタンでライト/ダークを切替、選択は `localStorage` に保存される。テーマ切替時はキャッシュ済みのレンダリング結果から現在のドキュメントを再構築する(ネットワーク往復なし)ため、SVGにテーマを焼き込むMermaid図は正しく再描画され、Shikiのコードブロックは再レンダリングなしでCSS変数により即座に切り替わる。

### 2.6 ライブリロード

`chokidar` によるファイル監視(複数ステップで書き込むエディタ対策として `awaitWriteFinish` でデバウンス)が、WebSocket(`/ws`)経由で2種類のメッセージを配信する。

- `doc-changed`: 表示中のドキュメントのレンダリングキャッシュを無効化し、スクロール位置を保ったままその場で再取得・再描画する。
- `tree-changed`: ファイル/フォルダの増減時にサイドバーのツリーを再構築する(300ms デバウンス)。

WebSocketクライアントは切断時に指数バックオフ(500ms〜上限5秒)で再接続し、再接続時にはオフライン中の変更を取りこぼしていないかツリーと現在のドキュメントを再同期する。CLIオプション `--poll` により、ネイティブの変更通知が信頼できないファイルシステム(一部のクラウド同期フォルダ等)向けにポーリング監視へ切り替えられる。

### 2.7 拡張性

アプリルートの `md-viewer.config.mjs` は起動時に読み込まれ、アプリ本体のコードを変更せずにremark/rehypeプラグインの追加やShikiテーマの上書きができる。

```js
export default {
  remarkPlugins: [somePlugin, [anotherPlugin, { option: true }]],
  rehypePlugins: [aRehypePlugin],
  shiki: { themes: { light: 'vitesse-light', dark: 'vitesse-dark' } },
}
```

ユーザープラグインは組み込み処理すべての後、最終的なHTML出力の直前に実行される。既定の設定ファイルには動作実証用の例(`rehypeExternalLinksNewTab`: 外部の `http(s)` リンクを新規タブで開く)が同梱されている。設定ファイルが存在しても不正な場合は、黙って無視せず起動時に明示的なエラーで停止する。

## 3. HTTP API

いずれもバインド先のホスト・ポート(既定 `127.0.0.1:8931`)で提供される。

| エンドポイント | 説明 |
| --- | --- |
| `GET /api/config` | `{ mode, rootName, rootPath, initialFile }` |
| `GET /api/tree` | `{ nodes: TreeNode[], count }` — 再帰的なツリー。Markdownを含まないフォルダは枝刈り |
| `POST /api/change-dir` | ボディ `{ path: "<絶対パス>" }`。既存のディレクトリであることを検証した上でサーバーのルートを切り替え(watcher再起動+レンダリングキャッシュ全消去)、`{ mode, rootName, rootPath }` を返す。絶対パスでない、またはディレクトリでない場合は `400`、存在しない場合は `404`。 |
| `GET /api/doc?path=<rel>` | `{ path, html, headings[], frontmatter, plain, mtimeMs }` — レンダリング済みドキュメント |
| `GET /api/search?q=<query>` | `{ query, results: [{ path, matches: [{line, snippet}], total }] }` |
| `GET /raw/<path>` | 画像等の生ファイル配信(ルート配下に限定) |
| `WS /ws` | ライブリロードのイベントストリーム(`doc-changed`, `tree-changed`) |

## 4. コマンドラインインターフェース

```
mdv [パス] [オプション]

  パス            表示する .md ファイル、またはフォルダ(省略時: カレントフォルダ)

  -p, --port N    ポート番号(既定 8931。使用中なら最大+9まで自動インクリメント)
      --host H    バインド先アドレス(既定 127.0.0.1)
      --no-open   起動時にブラウザを自動で開かない
      --poll      ポーリングでファイル監視
  -h, --help      ヘルプを表示
```

`npm start -- <引数>`、グローバルインストールした `mdv` コマンド、パッケージ化された `mdv.exe`(ポータブル版・インストーラー版)のいずれでも同一のCLI仕様(§6参照)。

## 5. セキュリティモデル

MD Viewer は**利用者自身のローカルファイル**を閲覧する用途に設計されており、既定で `127.0.0.1` にバインドされる。

- **HTMLサニタイズなし** — `rehype-raw` によりMarkdown内の任意のインラインHTMLがそのまま描画される。これは意図的な設計(GFM/HTML記述力の維持)だが、信頼できないMarkdownを開く場合は `md-viewer.config.mjs` 経由で `rehype-sanitize` を追加すべきである。
- **パストラバーサル対策** — リクエストに起因するファイル読み取り(`/api/doc`、`/raw/*`)はすべて、要求された相対パスを `path.resolve` で解決した上でルート配下に収まっているかを検証してからディスクにアクセスする。`..` によるルート外脱出要求には `400`/`403` を返す。
- **認証なし** — ログイン機構は存在しない。バインド先のホスト・ポートに到達できる者は誰でもルート配下の任意ファイルを読み取れる。信頼できないネットワークで `--host 0.0.0.0` を指定しないこと。
- **`POST /api/change-dir` はOSユーザーが読み取れる任意のディレクトリへサーバーのルートを切り替えられる** — 検証するのは「存在するディレクトリか」のみで、許可リストは持たない。これはこのツールの脅威モデル(認証なし・ループバック限定の個人用ビューア)と整合しているが、裏を返せば上記の「信頼できないネットワークにバインドしない」というルールの重要性がこれまで以上に高まったことを意味する。到達可能なホストでは、このエンドポイントにより遠隔の訪問者がマシン上の読み取り可能な任意フォルダにファイルブラウザを向けられてしまう。

## 6. 配布形態

### 6.1 ソースから起動

`npm install && npm start -- <パス>`。Node.js 20.6 以上が必要。

### 6.2 ポータブル版(`.zip`)

単体で完結するフォルダ構成。`mdv.exe` は Node.js公式の [Single Executable Applications](https://nodejs.org/api/single-executable-applications.html) 機能で作成した正真正銘の単一Windows実行ファイル(Node.js本体のコピーに、`postject` で小さなブートストラップ用blobを注入したもの)であり、隣接する `app/` フォルダにサーバー本体・クライアント資産・軽量化済みの `node_modules` を格納する(Mermaidのビルド時専用の巨大な依存関係 — `@mermaid-js/parser`、`cytoscape`、`cytoscape-fcose`、`d3`、`dompurify`、`es-toolkit` — はサーバーコードから `require()` されず、事前ビルド済みの `mermaid.min.js` のみが配信対象であるため除外している)。インストール不要・管理者権限不要・レジストリ変更なし。フォルダや `.md` ファイルを `mdv.exe` のアイコンへドラッグ&ドロップして開ける。一般ユーザー向けに、起動方法・フォルダ切替・注意点をまとめた `はじめにお読みください.txt`(日本語)を `mdv.exe` と同じ場所に同梱する。ビルドスクリプトが生成するため、バージョン番号は常に一致する。

### 6.3 インストーラー版(`.exe`)

[Inno Setup](https://jrsoftware.org/isinfo.php) でビルド。既定では管理者権限不要のユーザー単位インストール(`%LOCALAPPDATA%\Programs\MDViewer`)を行い、以下を含む。

- スタートメニューへのショートカット(アプリ本体・サンプル起動・`はじめにお読みください.txt`・アンインストーラー)
- デスクトップアイコン(対話式ウィザードでは既定でオン。ただし `/VERYSILENT` によるサイレントインストールでは `/TASKS="desktopicon"` を明示しない限り作成されない)
- 「PATHに追加」タスク(任意、既定オフ)— 有効にするとどのターミナルからも `mdv` コマンドが使える
- インストール完了直後に「はじめにお読みください.txt」を開くチェックボックス(任意、既定オフ)
- 標準的なWindowsのアンインストールエントリ(アプリと機能)— PATHに追加していた場合はアンインストール時に自動で削除

両パッケージともコード署名なし(証明書未取得)のため、初回起動時にWindows SmartScreenの警告(「WindowsによってPCが保護されました」)が表示される場合がある。個人配布の未署名ソフトでは想定内の挙動であり、「詳細情報」→「実行」で起動できる。

## 7. 性能特性(実測値)

Windows 11 / Node 25、500ファイルの合成データ(20フォルダ×25ファイル、各約2KB)での実測。

| 操作 | 実測値 |
| --- | --- |
| `GET /api/tree`(500ファイル全走査) | 5〜6ms |
| `GET /api/search`(500ファイル横断スキャン) | 74〜79ms |
| `GET /api/doc` 起動直後ウォームアップ後の初回レンダリング | 約223ms |
| `GET /api/doc` 2回目以降(未キャッシュ) | 8〜16ms |
| `GET /api/doc` キャッシュヒット(mtime+size不変) | 約2ms |

Shikiの文法・テーマエンジンの初期化(コールドで約4.5秒)はサーバー起動時のバックグラウンドウォームアップで1回だけ発生し、実際の初回リクエストには影響しない。レンダリング結果はキャッシュされ(mtime+sizeをキーに最大50件)、ファイル監視により正確に無効化される。

## 8. 既知の制限事項

- フォルダ横断検索は単純な大文字小文字無視の部分一致のみ。正規表現・ランキング・索引なし。
- ドキュメント編集機能はなし(閲覧専用として設計)。
- 自動テストスイートはなし。検証はAPI応答確認・DOM検証・実ファイル操作による観察を中心とした手動/スクリプトによるスモークテストで行っている。
- Windows 11でのみ動作検証済み。ソース起動であればmacOS/Linuxでも標準的なNode APIのみで構成されているため動作する見込みだが未検証。
- 未署名のWindowsバイナリのため、SmartScreenの「不明な発行元」警告が表示される。
